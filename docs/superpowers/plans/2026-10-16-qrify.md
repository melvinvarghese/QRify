# QRify Implementation Plan

> **For agentic workers:** Execute this plan task by task using the `executing-plans` workflow and test-driven development. Steps use checkbox syntax.

**Goal:** Build and deploy a responsive, privacy-first static QR code generator in the existing QRify repository.

**Architecture:** Keep the site static and root-relative to the GitHub Pages repository path, with pure payload/color/SVG logic separated from DOM event handling. Vendor the QR algorithm locally; keep user content in memory and render/download it in the browser.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript ES modules, `qrcode-generator@2.0.4` MIT, Node’s built-in test runner, existing GitHub Pages legacy publishing from `main`/root.

**Spec:** `docs/superpowers/specs/2026-10-16-qrify-design.md`

## Global Constraints

- No framework, backend, database, paid API, analytics, tracker, CDN dependency, or in-app build step.
- Use relative paths; the production base is `/QRify/`.
- Never persist or transmit user-provided QR content, and never render it as HTML or automatically navigate to it.
- Keep readable defaults: black foreground, white background, medium error correction, and 256 px output.
- Provide all six input modes, accessibility, privacy warnings, customization, PNG/SVG, copy, reset, documentation, and Pages deployment as specified.
- Commit complete, tested stages; push only the intended commits to the existing `origin/main`, without rewriting history.

## Review Focus

1. **Unicode payloads** can be corrupted if the UTF-8 helper is loaded late or not applied — test `buildPayload` with non-ASCII text and verify browser generation uses UTF-8.
2. **Wi-Fi reserved characters** can change SSID/password boundaries — test escaping of backslash, semicolon, comma, colon, and double quote in `buildPayload('wifi', ...)`.
3. **vCard text** with separators/newlines can create unintended fields — test escaping in the vCard payload builder.
4. **Empty input and unsafe URL schemes** must not produce a preview — test whitespace-only and `javascript:` URL values are rejected.
5. **Colorized exports** must remain consistent and safe — test SVG foreground/background, quiet zone, and escaping/validation, then compare browser PNG/SVG output colors.

### Task 1: Payload, color, and SVG core

**Files:**
- Create: `assets/js/qrify-core.mjs`
- Test: `tests/qrify-core.test.mjs`

**Interfaces:**
- Produces `buildPayload(mode, fields) -> string`; supported mode names are `url`, `text`, `email`, `phone`, `wifi`, and `contact`.
- Produces `contrastRatio(foregroundHex, backgroundHex) -> number`.
- Produces `svgFromMatrix(matrix, {size, foreground, background, quietZone}) -> string`, where `matrix` is a square `boolean[][]` and `quietZone` defaults to four modules.
- Validation failures throw an `Error` with a user-appropriate message; no input is logged.
